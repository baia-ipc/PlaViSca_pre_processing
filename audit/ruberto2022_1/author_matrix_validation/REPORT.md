# Ruberto2022_1 author count-matrix validation study

Status: **validation only. No production count matrix, study object, integrated
object, or application data was modified.** No cells were excluded. No
production script was changed. This task continues from, and does not repeat,
`audit/ruberto2022_1/AUDIT.md`, `D036_blocker_report.md`, and
`D036_resolution.md`, which established and characterized D036 (538/1,438
Ruberto2022_1 cells with near-total expression loss in PlaViSca's own
STARsolo reconstruction, concentrated in runs SRR19573609/610). This task asks
a narrower question: **can the author-provided `Hep59.1.2.seu_20aug2025.rds`
count matrix be scientifically justified as a replacement input for all 1,438
Ruberto2022_1 cells?** Group A (the 538 D036 cells) and Group B (the remaining
900 cells) are used exactly as defined by the authoritative
`near_empty_cells_vs_hep59.tsv` cell list; no new threshold was invented.

Commit baseline: `d40a3bb346d35be9983d3f74c6cb95fe8cd960c7` (branch
`plavisca-production-repair`). All analysis in this report was generated by
`validate_author_matrix.R` in this directory; full console output is saved as
`validate_author_matrix.log`.

## 3. Proof of raw UMI counts (Q2)

Object structure (`Hep59.1.2.seu_20aug2025.rds`):

- Seurat object version **4.0.3** (historical build; this repository's
  environment uses Seurat 5.3.0 to read it, no incompatibility encountered).
- Single assay: `RNA`. **No SCT assay is present** in this file
  (`Assays(hep59)` returns only `"RNA"`), even though `nCount_SCT` /
  `nFeature_SCT` / `SCT_snn_res.*` columns remain in `meta.data` — these are
  leftover metadata from an SCTransform step recorded in `@commands` upstream
  of this particular export; the SCT assay object itself was not retained in
  this file. **This means an SCT-vs-RNA-counts distinction cannot be
  demonstrated directly from this file** (there is no SCT assay to compare
  against) — see "still requiring confirmation" below.
- `RNA` assay: **4,722 features × 1,438 cells**, layers `counts`, `data`,
  `scale.data`.

### Integer test

| Metric | Value |
|---|---:|
| Matrix entries (4,722 × 1,438) | 6,790,236 |
| Nonzero entries | 1,304,687 |
| Non-integer nonzero entries | **0** |
| Minimum nonzero value | 1 |
| Maximum nonzero value | 1,655 |

Every nonzero entry in `counts` is a non-negative integer. This is exactly
the signature of raw UMI counts.

### Count-total test

| Metric | Value |
|---|---:|
| Cells where `colSums(counts) == nCount_RNA` | 360 / 1,438 |
| Cells where they differ | 1,078 / 1,438 |
| Max absolute difference | 2,448 |
| Cells where `colSums(counts) > nCount_RNA` | **0** |

The discrepancy is **strictly one-directional**: `colSums(counts)` never
exceeds `nCount_RNA`, in any of the 1,438 cells. This pattern is exactly what
is expected if `nCount_RNA` was computed upstream on a **combined
human+P. vivax** count matrix — consistent with the recovered
kallisto|bustools workflow (`D036_resolution.md`: `kallisto bus -x 10xv3`
against a combined `Homo_sapiens.GRCh38.cdna.all` + PlasmoDB-51 index) —
*before* this particular exported file's `RNA` assay was subset down to the
4,722 P. vivax-only features. A raw-count matrix that has been feature-subset
after `nCount_RNA` was first computed will always show `colSums ≤ nCount_RNA`,
never `>`, which is exactly what is observed. **This does not indicate the
retained counts are non-raw or corrupted; it means `nCount_RNA` cannot be
exactly reconciled from this parasite-only export alone** — a labeled,
understood limitation, not an open red flag. (`nFeature_RNA` shows the
identical 360/1,078 pattern for the same reason.)

### Normalized-data distinction

- `counts` and `data` layers are **not identical** (checked directly, not
  inferred from naming).
- `data` layer nonzero values are **not all integers** (sample checked), and
  its maximum value is **7.90**, versus a `counts` maximum of **1,655** — the
  compressed dynamic range and non-integer values are the expected signature
  of `NormalizeData()`-style log-normalized expression, not raw counts.
- No SCT assay is present in this file to additionally compare against (see
  above).

**Conclusion (Q2): CONFIRMED RAW UMI COUNTS** for the `RNA` `counts` layer —
100% integer, non-negative, distinct from a separately-normalized `data`
layer with the expected log-scale signature. The only residual uncertainty is
that `nCount_RNA`/`nFeature_RNA` reflect a pre-subset combined-genome object
and so cannot be used for an exact reconciliation from this file in
isolation; this is explained, not unexplained, and does not bear on whether
`counts` itself is raw.

Full table: `rna_counts_validation.tsv`.

## 6/7. Expression concordance for the 900 unaffected cells (Group B), overall and by run

### Method note (important; read before the numbers)

A first pass used the literal "genes expressed in at least one of the two
representations" (union-of-nonzero) rule suggested as a default strategy.
This produced **systematically negative** per-cell Spearman correlations even
for the best-behaved control cells (median ≈ −0.36 in Group B overall),
directly contradicting strongly positive signal seen in every other
independent test (cell-identity ranking, pseudobulk correlation, full-panel
correlation). Diagnosis on a representative run-612 cell: author nonzero
genes = 951, PlaViSca nonzero genes = 373, intersection = 196, union = 1,128.
`spearman(union) = −0.396` vs `spearman(intersection) = +0.318`,
`spearman(full 4,722-gene panel) = +0.241`. The union rule was dominated by
~930 genes detected by only one of the two methods (author-side kallisto
detects several-fold more genes per cell here than PlaViSca-side STARsolo),
each contributing a one-sided tie at zero; with this much detection-sensitivity
asymmetry, the union rule's rank-tie structure biases the correlation
negative — an artifact of the rule, not evidence against concordance.

Per the task's own allowance for "another defensible sparse-data strategy,"
the **primary reported metric is intersection-of-nonzero** (genes detected in
*both* representations for that cell, ≥5 required to compute a value), which
removes the one-sided-detection noise while still avoiding domination by
joint zeros. **Full-panel** correlation (all 4,722 shared genes, including
joint zeros) is reported alongside as an independent robustness check, and
agrees in sign and relative ordering throughout. Union-of-nonzero is not used
further in this report.

### Group B (900 cells), overall

| Metric | Value |
|---|---:|
| n with computable intersection-Spearman (≥5 shared-nonzero genes) | 843 / 900 |
| Median Spearman (intersection-nonzero) | **0.342** |
| IQR (intersection-nonzero) | 0.240 – 0.426 |
| Median Spearman (full panel, robustness check) | 0.265 |
| IQR (full panel) | 0.226 – 0.308 |
| Median detected genes, author (shared panel) | 699 |
| Median detected genes, PlaViSca (shared panel) | 269 |

Both metrics agree: **Group B shows a clear, biologically credible positive
concordance** between the two independently-generated count matrices,
despite different aligners (kallisto vs STARsolo), different references
(PlasmoDB-51 transcriptome vs PlasmoDB-68 genome), and materially different
per-cell detection sensitivity (author matrix detects ~2.6× more genes/cell
on the shared panel).

## 7. Run-specific controls: 611/612 vs the residual 609/610 cells

**SRR19573611 and SRR19573612 (positive controls, 891 of the 900 Group B
cells, 99%):** both show consistent, unambiguous positive concordance
(median intersection-Spearman 0.37 and 0.32 respectively; pseudobulk Spearman

**Residual non-D036 cells from SRR19573609/610 (9 cells total: 1 from 609, 8

the 611/612 pattern; the single 609 cell cannot be rank-tested at all (a pool

**These few recoverable 609/610 cells show behavior compatible with, but not
independently powerful evidence for, the same conclusion as 611/612** — the
strength of the overall Q1 conclusion rests on 611/612, not on this small
residual set.

## 9. Cell-identity (rank) test

For each author cell, spearman correlation (full shared 4,722-gene panel) was
computed against every PlaViSca cell in the same run and same group, and the
rank of the true corresponding PlaViSca barcode recorded.

| Run | Group | n candidates | Rank-1 | Top-5 | Top-10 |
|---|---|---:|---:|---:|---:|
| SRR19573611 | unaffected | 255 | **100.0%** | 100.0% | 100.0% |
| SRR19573612 | unaffected | 636 | **84.9%** | 87.4% | 93.1% |
| SRR19573610 | unaffected | 8 | 0.0%† | 87.5%† | 100.0%† |
| SRR19573609 | unaffected | 1 | n/a (pool size 1) | n/a | n/a |
| SRR19573610 | D036 near-empty | 15‡ | 6.7% | 26.7% | 60.0% |
| SRR19573609 | D036 near-empty | 6‡ | 33.3% | 83.3% | 100.0% |

†n=8 candidates; rank-1 by chance alone would be 12.5%, top-5 62.5% — the
observed top-5/top-10 are above chance but the sample is too small for a
confident claim; rank-1=0% with n=8 is a single miss, not a systematic
failure.
‡Most of the 538/449/89 D036 cells have an all-zero or single-nonzero
PlaViSca profile with zero variance, which cannot be rank-correlated at all
(`cor()` is undefined for a constant vector); only cells with nonzero
variance on the PlaViSca side survive into a candidate pool at all, which is
why n=15/6 rather than 449/89.

**This is the single strongest piece of provenance evidence in this study.**
For SRR19573611 (n=255 candidates), the true match is ranked first **100% of
the time** — the random-chance rate for a 255-candidate pool is 0.39%. For
SRR19573612 (n=636 candidates), the true match is ranked first **85% of the
time** (chance rate 0.16%), rising to 93% within the top 10. Pooling 611+612
(891 of the 900 Group B cells): **~89% rank-1 hit rate**, an outcome that
cannot occur by chance and is only explicable if the author and PlaViSca
matrices for these cells describe the same underlying biological cell.

By contrast, the D036 near-empty candidate pools (15 and 6 candidates,
respectively) show rank-1/top-5 rates **statistically indistinguishable from
random chance** (random rank-1 for n=15 is 6.7% — exactly what was observed;
random top-5 for n=15 is 33% vs observed 27%). This is the expected null
result given PlaViSca's own signal for these cells is confirmed near-absent,
and it is a useful negative control demonstrating the identity test's
specificity: it finds strong signal where signal should exist (611/612) and
finds none where none should exist (D036 cells), rather than showing an
inflated rank-1 rate everywhere as a methodological artifact would.

Full table: `cell_identity_test.tsv`.

## 11. Suitability assessment

### A. Same biological dataset?

**STRONG EVIDENCE.**

- Exact, assertion-enforced 1:1 cell crosswalk (Section 1): 0 unmapped, 0
  duplicated, either direction.
- Zero metadata disagreements across all 1,438 cells on every comparable
  field (day, replicate, liver_form, run-prefix mapping) (Section 2).
- Consistent, reproducible positive expression concordance for the 900
  unaffected cells by every metric tried (per-cell intersection-Spearman,
  per-cell full-panel Spearman, pseudobulk Spearman/Pearson) (Sections 6–8).
- A rank-1 cell-identity match rate of 85–100% against same-run candidate
  pools of 255–636 cells (chance rate 0.16–0.39%), specifically and only for
  the cells where PlaViSca's own signal is confirmed real; a null result for
  the D036 cells where it is confirmed absent (Section 9).

### B. Raw UMI matrix?

**CONFIRMED RAW UMI COUNTS.**

- 100% integer, non-negative nonzero values (1,304,687 nonzero entries
  checked, 0 non-integer).
- Clearly distinct from a co-resident, non-integer, compressed-dynamic-range
  `data` layer with the expected log-normalized signature.
- The only imperfection is that `nCount_RNA`/`nFeature_RNA` cannot be
  reconciled exactly against this file's own `counts` layer — fully explained
  as inherited metadata from an upstream combined human+parasite object,
  strictly one-directional (`colSums(counts) ≤ nCount_RNA` in 100% of cells,
  never the reverse), consistent with subsequent feature-subsetting to
  parasite-only genes. This does not indicate the counts themselves are
  non-raw.

### C. Gene-space compatibility?

**DIRECTLY COMPATIBLE.**

- 4,722 / 4,722 (100%) author features are exact, unambiguous string matches
  to PlaViSca's 6,811-feature panel.
- 0 unmapped, 0 ambiguous, 0 duplicated, 0 one-to-many/many-to-one mappings.
- No version-suffix or naming-convention normalization was needed.
- Using the author matrix would zero-fill PlaViSca's 2,089 additional
  features not present in the author's smaller reference-derived panel — a
  deterministic, lossless, fully documented operation.

### D. Suitable replacement for STARsolo Ruberto2022_1?

**Technical recommendation: use the complete author matrix for all 1,438
cells**, conditioned on:

1. Adding an explicit `source_of_counts` (or equivalent) provenance field
   distinguishing these 1,438 cells' counts as author-derived
   (kallisto|bustools, PlasmoDB-51) rather than PlaViSca's own STARsolo
   (PlasmoDB-68) pipeline used for the other five studies — this is a real,
   documented methodological difference (different aligner, different
   reference version/scope, different cell-calling method, different
   software era; already flagged in `D036_resolution.md`) and must remain
   visible in the data, not silently absorbed.
2. Explicit project-lead sign-off, given this substitutes the *entire*
   study's counts (not just the 538 D036 cells) with a matrix generated by a
   materially different pipeline than the rest of the PlaViSca atlas.
3. Retaining the byte-level Zenodo-provenance and pre-deposit-vs-SRA-deposit
   questions in Section 12 as still-open, since they bear on how much
   confidence to place in this specific dated local file as *the* canonical
   published object, even though they do not undermine the computational
   concordance evidence gathered here.

This is a firmer conclusion than `D036_resolution.md`'s prior "possible
alternative, requires approval" ranking for option 2, because that prior
evaluation had not yet performed the crosswalk validation, metadata
concordance, raw-count proof, gene-mapping quantification, or (most
importantly) the cell-identity rank test in Section 9, all of which now
independently and convergently support the same conclusion.

**Computationally established in this task** (with quantitative support
above): identical 1,438-cell inventory across author/PlaViSca/deployed;
zero day/replicate/liver-form/run-mapping metadata disagreements; raw-count

and a sharp, expected contrast against the 538 D036 cells.

**Still requiring author confirmation** — this study does **not** claim that
`Hep59.1.2.seu_20aug2025.rds` is proven byte-identical to the canonical
object used for publication. That requires direct confirmation from
Ruberto/the original authors or a checksum match to the canonical Zenodo
deposit. The smallest set of outstanding questions:

   `outputs/Hep59.1.2.seu.rds` in the Zenodo deposit
   (10.5281/zenodo.6463338), so it can be compared against our locally dated
   copy `Hep59.1.2.seu_20aug2025.rds` (MD5
   `203013218936548744516954cb73c39e`)?
2. Was this object's RNA counts built from the exact SRA/ENA FASTQ files
   deposited under BioProject PRJNA843856 (SRR19573609–612), or from an
